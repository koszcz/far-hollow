# 09: Give each animation showcase its own file, so two new showcases merge cleanly

**What to build:** Each animation showcase, such as `fishing-animation` or `sled-rope`, lives in its own file. A registry of the animation showcases is marked `merge=union` in `.gitattributes`. Two branches that each add a showcase merge without a conflict.

**Blocked by:** None

**Status:** resolved

**Assets:** None. This ticket changes no asset. Every showcase must look the same before and after.

On 2026-11-21, landing two asset branches hit merge conflicts in `src/render/showcases/animations.ts` (664 lines), as well as in the player mesh. Triage split the showcase half out of ticket 08, because it does not depend on the motion modules. It can land before or after ticket 08. Read ADR 0012.

## Agent Brief

**Category:** enhancement

**Summary:** Split the animation showcases into one file each, listed in a registry that git merges by union.

**Current behavior:**

- `ANIMATIONS_SHOWCASES` holds every animation showcase in one file, keyed by asset id. Examples are `sled-drag-animation`, `sled-rope`, `chop-animation`, `fishing-animation`, and `forage-eat-drink-animation`.
- The file also holds helpers and constants that some showcases share. For example, `sled-rope` spreads `SLED_DRAG_SHOWCASE` and changes its framing.
- The showcase registry, `SHOWCASES`, spreads `ANIMATIONS_SHOWCASES` together with the other families.
- A new animation showcase adds an entry in the middle of that one file. Two branches doing this edit nearby lines and conflict.

**Desired behavior:**

- Each animation showcase lives in its own file, in a folder for the animation showcases. Each file exports one `Showcase`.
- Helpers and constants that more than one showcase uses go in one shared file in that folder. A helper used by one showcase moves into that showcase's file.
- An animation showcase registry lists every file, one line per showcase, and still exports `ANIMATIONS_SHOWCASES` with the same keys.
- `.gitattributes` marks that registry `merge=union`, as ADR 0012 sets out.
- `SHOWCASES` and every showcase URL, `/?asset=<id>`, work as before.

**Key interfaces:**

- `Showcase`, `Shot`, and `Stage` in the showcase types: do not change them.
- `ANIMATIONS_SHOWCASES`: same keys and same values. Only where each value lives changes.

**Acceptance criteria:**

- [x] Every key in `ANIMATIONS_SHOWCASES` has its own file, and the registry adds each in one line.
- [x] `.gitattributes` marks the registry `merge=union`.
- [x] A test shows that `ANIMATIONS_SHOWCASES` has the same keys as before the split.
- [x] A scratch check proves the merge works. Make two throwaway branches, each adding a showcase line to the registry. Merge both into a third throwaway branch with no conflict, then delete all three. Record the result in the commit message.
- [x] For each animation showcase, `bun scripts/shot.ts "/?asset=<id>" <out.png>` is run on `main` and on the branch. A script compares each pair. Do not open the images yourself (see `docs/agents/game-testing.md`). Any pair that differs beyond a small threshold is listed for the owner to check by eye before landing.
- [x] `bun test` and `make check` pass.

**Out of scope:**

- Splitting the other showcase families, such as camp, building, nature, interface, or weather.
- Moving player motions out of the player mesh. That is ticket 08.
- Changing what any showcase shows.
