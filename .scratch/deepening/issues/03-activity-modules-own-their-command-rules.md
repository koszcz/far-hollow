# 03: Each activity module declares its own command rule

**What to build:** Each activity module, such as `fishing.ts` or `beds.ts`, exports the command rules for its commands. `src/sim/game.ts` collects them instead of writing each rule itself. A new command needs edits in its own activity module, the UI, and strings, and nowhere else in the sim.

**Blocked by:** 01, 02, 04, 07

**Status:** resolved

**Assets:** None. This ticket changes no asset.

## Why

`commandRules` in `src/sim/game.ts` is a good seam, but most rules only forward to an activity module. One command's meaning is spread over:

- the `Command` union in `src/sim/api.ts:46-221`;
- its rule in `src/sim/game.ts:480-790`;
- for tend commands, also `TendTask` (`src/sim/entities.ts:29-35`), `TEND_REACH` (`game.ts:75-90`), the `tendNow` switch (`game.ts:372-413`), and two `placeOf` lookups (`game.ts:427` and `src/sim/tending.ts:26`);
- its task component in `src/sim/entities.ts`;
- its save check in `src/sim/save-schema.ts`;
- `TASK_PARTS` in `src/sim/activity.ts`.

A new refusal also needs `PlainRefusal` (`api.ts:454`) and `PLAIN_REFUSALS` (`save-schema.ts:156`). A new notice needs `notices.ts`, `save-schema.ts:193`, and `api.ts:344`.

Tickets 01, 02, and 07 remove the per-kind task components and the duplicated refusals. Ticket 04 adds a stop check to the rule shape. After them, most of what is left in each rule belongs to its activity module.

## What to do

## Agent Brief

**Category:** enhancement

**Summary:** Each activity module exports the command rules for its own commands. `commandRules` in `game.ts` only collects them.

**Current behavior:**

- `commandRules` in `game.ts` writes one `CommandRule` per command type. Most rules only forward to an activity module.
- Tend commands are spread over `TendTask`, the `TEND_REACH` table and the `tendNow` switch in `game.ts`, and two `placeOf` lookups, one in `game.ts` and one in the tending module.
- By the time this ticket starts, tickets 01, 02, 04, and 07 have landed. Walks go through the approach. Refusals are checked before `run`. The rule shape has a stop check for actions with no end. Read those tickets' agent briefs and ADR 0010 first.

**Desired behavior:**

- Each activity module exports the rules for its commands, in the `CommandRule` shape. A rule holds that command's refusal, its approach target and act step, its stop check, and its other flags.
- `commandRules` in `game.ts` lists each module's rules and nothing else. TypeScript still reports a command type with no rule.
- `game.ts` keeps only what every command shares: hands busy with a sled, standing up from a stool, cancelling tasks, and calling the action queue.
- The `Command` union stays in `api.ts`, written by hand. It is the one readable contract between the UI and the sim (ADR 0005).
- Save checks stay hand-written in `save-schema.ts`. The approach saves a `Command`, so the save check for commands stays in step with the union by hand.
- Tend commands:
  - The tending module owns the reach height for each tend command, which `TEND_REACH` holds today.
  - The tending module holds the one place lookup. The second `placeOf` goes away.
  - Each tend command's act step lives in the module that does the work, such as campfires, woodpiles, sleds, pot, or cooking. The `tendNow` switch goes away.
- A comment beside `commandRules` lists the files a new command touches.
- The game plays exactly as before.

**Key interfaces:**

- `CommandRule` and `CommandRules`: export them from a place that activity modules can import without importing `game.ts`.
- Each activity module's factory, such as `createFishing`: also returns, or exports, the rules for its commands.
- `TendTask`: may stay as the type for tend commands. Its reach and place lookup live in the tending module.

**Acceptance criteria:**

- [x] `commandRules` in `game.ts` lists modules' rules. It holds no per-command logic.

- [x] Adding a command touches its activity module, the `Command` union in `src/sim/api.ts`, the save check for commands in `src/sim/save-schema.ts`, the UI files that offer it, and `src/strings.ts`. A comment in `game.ts` lists these files.
- [x] `TEND_REACH` and `tendNow` are gone from `game.ts`. One place lookup for tend commands remains, in the tending module.
- [x] The first commit moves fishing. Each later commit moves one module. The tests pass after each commit.

**Out of scope:**

- Building the `Command` union from the modules' declarations.
- Deriving save checks from the rules, or replacing `save-schema.ts`.
- Moving refusals or notices out of `api.ts`, `notices.ts`, or `save-schema.ts`.
- Changing how any command plays.
