# 05: Furniture is one kind of pick, and each definition names its use

**What to build:** When the player points at a piece of furniture, the pick says "furniture" and names the piece. Each furniture definition says which command using it sends, if any. The action menu reads that from the definition instead of switching on each piece.

**Blocked by:** None

**Status:** ready-for-agent

**Assets:** None. This ticket changes no asset.

## Why

The comment at the top of `src/sim/furniture.ts` lists 11 places to edit for a new piece. Some of them belong apart, such as the mesh, the showcase, and the build menu icon. Two of them exist only because each piece is its own kind of pick:

- `src/sim/reach.ts:50` turns `entity.furniture` into its own pick kind, so `ScenePick` and `ThingInReach` grow by one variant per piece.
- `thingActions` in `src/app/thing-actions.ts:143-152` has one case per piece: open for a chest or shelf, sleep for a bed, nothing for a table, and sit for a stool.

`src/sim/beds.ts` and `src/sim/stools.ts` also check the piece by name when they look it up.

## What to do

1. Change the pick for furniture to one kind that names the piece and its id.
2. Add the use to each definition in `src/sim/furniture/*.ts`: a sim-side use name and the command it sends, or none. Keep labels, icons, and order in the UI, as ADR 0008 requires. The definition names a use, not text and not a UI action id. See the agent brief below.
3. Replace the per-piece cases in `thingActions` with one furniture case that reads the definition.
4. Remove the line for the menu from the checklist in `src/sim/furniture.ts`.

## Acceptance criteria

- [ ] `ScenePick` and `ThingInReach` have one variant for furniture.
- [ ] `thingActions` has no case for a single piece of furniture.
- [ ] Each piece offers the same actions as before. The furniture cases in `src/app/thing-actions.test.ts` pass.
- [ ] Adding a piece needs no edit to `src/sim/reach.ts` or `src/app/thing-actions.ts`.
- [ ] Existing tests pass, including `src/sim/furniture.test.ts`.

## Agent Brief

**Category:** enhancement

**Summary:** Make finished furniture one kind of pick, and let each furniture definition say how the player uses it, so a new piece needs no edit to the pick code or the action menu.

**Current behavior:**

- Each piece of furniture is its own pick kind. The `ThingInReach` kind union includes every `FurnitureKind`, so `ScenePick` grows by one variant per piece.
- `thingActions` has one case per piece. A chest or shelf offers "open" (`openChest`). A bed offers "sleep" (`sleepInBed`). A stool offers "sit" (`sitOnStool`). A table offers only "take down". Every piece also offers "take down".
- The checklist comment at the top of the furniture module lists the `thingActions` switch as a place to edit for each new piece.

**Desired behavior:**

- Finished furniture gives one pick: `{ kind: "furniture"; id: number; furniture: FurnitureKind }`.
- `FurnitureDefinition` gets an optional `use` field. It holds a sim-side use name and a function that builds the command from the piece's entity id. For example: `use?: { readonly name: "open" | "sleep" | "sit"; readonly command: (id: number) => Command }`. A table has no `use`.
- The use name is a sim type. The sim must not import `ActionId` or any other type from the UI.
- The action menu has one furniture case. It reads the definition's `use`. It maps the use name to the action id, label, and icon. If there is a use, that action comes first and is the main action. "Take down" always comes last.
- The checklist comment no longer lists `thingActions`. It does not need a line for the pick either, because the pick already comes from `entity.furniture`.

**Key interfaces:**

- `ThingInReach`: furniture kinds leave the plain-kind union. One new `furniture` variant takes their place.
- `ScenePick` and `GroundOrThingPick`: take the new variant through `ThingInReach`. Check every caller that narrows on `kind`, including the cursor, the outline, and the walk input.
- `FurnitureDefinition`: the new optional `use` field.
- `thingActions`: one `furniture` case in place of the five per-piece cases.
- The commands `openChest`, `sleepInBed`, and `sitOnStool` keep their shapes. Each one names its id field differently (`chestId`, `bedId`, `stoolId`). That is why the definition builds the command.

**Acceptance criteria:**

- [ ] `ThingInReach` and `ScenePick` have exactly one variant for finished furniture.
- [ ] `thingActions` has no case that names a single piece of furniture.
- [ ] Each piece offers the same actions as before: the same ids, labels, icons, commands, order, and main action. The furniture cases in the thing-actions tests pass, rewritten only for the new pick shape.
- [ ] Hovering a piece of furniture still shows the hand cursor and the outline.
- [ ] No file under the sim imports from the UI.
- [ ] Adding a piece of furniture needs no edit to the reach code or to `thingActions`. A short test or a type check shows this, for example a definition with no `use` gets only "take down".
- [ ] The checklist comment in the furniture module no longer lists `thingActions`.
- [ ] All existing tests pass, including the furniture tests. `make check` passes.

**Out of scope:**

- Changing the `openChest`, `sleepInBed`, or `sitOnStool` commands.
- Changing how `beds.ts` and `stools.ts` find their piece by name.
- Blueprints of furniture. They stay `blueprint` picks.
- Moving `ScenePick` out of the renderer. Ticket 06 does that. Ticket 06 also edits the action menu file, so whichever ticket lands second rebases onto the first.
- Any change to how the game plays.
