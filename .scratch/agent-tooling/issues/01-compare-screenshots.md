# 01: Compare a page's screenshots on two commits

**What to build:** `scripts/shot.ts` gets a `--compare <commit>` option. It takes the screenshot on the current code and on the given commit, then prints how many pixels differ and where. An agent can then check that a refactor left a page looking the same, without reading either image.

**Status:** ready-for-agent

**Assets:** None. This ticket changes no asset.

## Why

On 2026-11-21, three sessions checked that a render refactor left showcases unchanged: the fireplace fire effect, and the lean-to, log wall, and sled drag animation in the value-objects work. Each one did it by hand:

1. It added a detached git worktree at the old commit and linked `node_modules` into it.
2. It ran `shot.ts` in both folders.
3. It wrote a Python script to compare the images. Every one failed, because Python's image library (PIL) is not installed.

The fallbacks were worse:

- `cmp` only says whether two files are byte-for-byte identical. Renders that vary a little between runs showed as different, so the agent had to take the shots again to tell noise from change.
- Reading both PNGs puts two images into context for the rest of the session. `docs/agents/game-testing.md` explains why that is expensive.

## What to do

1. Add `--compare <commit>` to `scripts/shot.ts`. Build the old shot from a temporary worktree at that commit, and remove the worktree afterwards.
2. Compare the two images without new system tools. One option: load both PNGs into the Playwright page that `shot.ts` already opens, draw them on a canvas, and compare the pixel data. A small PNG package from npm is another option.
3. Print the share of pixels that differ by more than a small threshold, and the box that holds them. Exit with a non-zero code when the share is above a limit that a `--tolerance` option sets.
4. Save a diff image next to the output file, for the cases where someone needs to look.
5. Document the option in the header of `shot.ts`, in `docs/agents/game-testing.md`, and in the `shot` target of the `Makefile`.

## Acceptance criteria

- [ ] `bun scripts/shot.ts "/?asset=fire-effect" /tmp/fire.png --compare HEAD` reports no difference.
- [ ] A commit that moves a mesh reports a difference, with its box.
- [ ] Small run-to-run noise stays under the default tolerance. A test or a repeated run shows this.
- [ ] The temporary worktree is gone after the run, including when the run fails.
- [ ] No Python and no system image tools are needed.

## Agent Brief

**Category:** enhancement
**Summary:** Add a `--compare <commit>` option to the screenshot script. It shoots the page on the current code and on an older commit, then reports how much and where the two shots differ.

**Current behavior:**
The screenshot script starts a dev server from its own checkout and saves one or more PNG files. It can't compare anything. Agents who check that a refactor left a page unchanged set up a second worktree by hand and then compare the images. Their compare scripts fail because Python's image library (PIL) is not installed on this machine. Their fallbacks either can't tell small noise from real change (`cmp`) or load both images into context.

Triage confirmed that the repo has no screenshot comparison yet and that PIL is missing. Asset showcases draw a still image unless `play` is set. Differences between two runs of the same code should therefore be small rendering noise, not animation frames.

**Desired behavior:**

1. `--compare <commit>` takes the usual shot (or shots) on the current working tree, including uncommitted changes. It then takes the same shots on the given commit.
2. The old shots come from the old commit's code. The script creates a temporary detached worktree at that commit in the system temp folder, not under `.claude/worktrees/`. It links the current `node_modules` into the worktree and starts that worktree's dev server. The current script logic drives the browser for both runs. That way, the old commit doesn't need to have `--compare`, or even the screenshot script.
3. The script removes the temporary worktree when the run ends. This includes a failed run and an interrupted one (Ctrl-C).
4. For each pair of shots, the script prints the share of pixels that differ by more than a small per-pixel threshold, and the box that holds those pixels (x, y, width, height). With `--at`, it compares the shots taken at the same time with each other and reports each pair.
5. The script saves a diff image next to each output file, such as `out-diff.png`. Agents should not need to open it. It is there for the owner.
6. The script exits with a non-zero code when any pair's share of differing pixels is above the limit. A `--tolerance` option sets the limit. Pick a default that hides run-to-run noise on a still showcase.
7. All other options (`--hover`, `--click`, `--press`, `--element`, `--wait`, `--size`) work the same way in both runs.

**Key interfaces:**

- The script's command line: new `--compare <commit>` and `--tolerance <share>` options. Document them in the script's header comment, in the usage error message, in the game-testing guide, and in the `shot` target of the `Makefile`.
- The function that starts the dev server must accept the folder to serve from. Today it always uses the script's own folder.
- Image comparison must not need Python or system image tools. Either draw both PNGs on a canvas in the Playwright page the script already opens, or add `pngjs` and `pixelmatch` as dev dependencies. Do not import Playwright's internal comparison code. It is not a public API.

**Acceptance criteria:**

- [ ] `bun scripts/shot.ts "/?asset=fire-effect" /tmp/fire.png --compare HEAD` on a clean tree reports no difference over the tolerance and exits with 0.
- [ ] A local change that moves a mesh in a showcase is reported as a difference, with a box around the moved part. The script exits with a non-zero code.
- [ ] Running the same compare several times on unchanged code stays under the default tolerance every time.
- [ ] `--compare` with `--at 0,0.5` reports one result per time.
- [ ] No temporary worktree is left in `git worktree list` after a successful run, a failed run (for example, a bad path), or an interrupted run.
- [ ] A diff image is saved next to each output file.
- [ ] A commit that doesn't exist gives a clear error message and leaves no worktree behind.
- [ ] Without `--compare`, the script behaves exactly as before.

**Out of scope:**

- Comparing against saved baseline images, as visual regression tests do.
- Adding screenshot comparisons to `bun test` or to the Playwright browser tests.
- Comparing two commits that are both different from the working tree.
- Installing dependencies in the old commit's worktree. It reuses the current `node_modules`, even when the old lock file differs.
